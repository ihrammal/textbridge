Report a Problem

Choose Help > Report a Problem. In the English interface, Alt+H then P opens it. Reporting is optional; preparing or saving a report does not send it.

What to include

  1. Enter the required Summary and Actual behavior fields.
  2. Add steps and expected behavior. For OCR, identify the engine, languages and type of source. For accessibility, include the screen reader/version, interface language, exact keys and missing or unexpected speech/focus.
  3. Review the read-only preview. Exclude passwords, API keys and private document text.
  4. Optional basic diagnostics are off by default. They contain runtime/OS availability details, not attached documents, paths, credentials or logs. Text you type yourself remains part of the preview.

Choose where the report goes

  • Save report writes a local text file. Copy report copies the preview for you to paste where you choose.
  • Email report opens a draft to iman.rammal@gmail.com in your email application. You review and send it yourself.
  • Report on GitHub opens an issue draft in the project repository. It can place entered report text in the browser URL. Review it before submitting; public issues are visible to other people. The app does not submit it automatically.

A long report may need saving and manually attaching to your email or issue. No source document or screenshot is attached automatically. Closing an unexported report offers to save it or keep editing.
